# Filesystem snapshot and admission contract

RAMNest admits ordinary files, directories and single-name symbolic links owned by the current uid and primary gid. ACL-bearing roots or descendants, incompatible ownership, hardlinked symbolic links and special files are rejected before conversion moves originals. Native import repeats the security admission walk before creating nodes; the native hardlink callback rejects symbolic links. Supported ordinary metadata includes exact modes, allowed UF_HIDDEN/UF_NODUMP flags, extended attributes (including exact quarantine), regular-file mtime and regular-file hardlink groups. Kernel decmpfs storage is represented by decoded logical bytes rather than replayed APFS compression metadata. Extended attributes are limited to 1 MiB per value, and native live nodes to 100,000. These limits apply to the root as well as descendants where relevant.

The public data root has its own manifest metadata. Private revision/session containers remain owned 0700 directories. Moving originals into private holding does not make the holding container's mode the public root's mode. Mounted population verification retains only the separately approved directional missing UF_HIDDEN/UF_NODUMP tolerance; ordinary snapshot verification is strict.

Entry and Manifest equality is exact, including optional allocation/root metadata. Compatibility is directional: an expected historical manifest without those fields may omit their validation. An observed missing field cannot satisfy a new expected field. Historical large-file full SHA-256 manifests remain readable; new large sparse content uses the versioned sparse64-v1 checksum. All source, candidate and readback digests are scoped to a checked transaction; timestamps alone never authorize reuse.

Logical quota counts occupied nonzero 64 KiB file pages, symlink target bytes and xattr names/values, once per inode. Apparent sparse size may exceed capacity. Truncate/regrow clears suffix data. Shared immutable export pages do not keep a deleted live inode charged after its final namespace/handle owner closes. Physical mapped/payload metrics count each backing until its actual final owner unmaps it, including export pins and staged replacements. The legacy four-number metrics and six-field status replies retain their shape.

One native export runs per volume. Physical backing admission is bounded by live capacity + min(capacity, 64 MiB) + 4 MiB, including pinned old mappings and staged atomic requests. Admission returns ENOMEM before exceeding that bound; callers can retry after export releases pins. Export snapshot namespace/metadata/page-index copies have an explicit cap of max(1 MiB, min(metadataBudget(capacity), 128 MiB)); exhausting it aborts capture without changing the live tree. Decoded export buffers are two 64 KiB heap buffers. Compression workspaces are per worker, bounded, and do not retain a decoded file cache. These are component bounds, not a promise that total process RSS equals logical capacity.

A save captures a coherent immutable generation under the tree lock, then releases that lock before disk writes, fsync and independent readback. Subsequent writes remain dirty for the next save. Unchanged regular files use verified independent clones/copies; mutable stages are never hardlinked into prior revisions. A validated no-op reuses the committed revision while retaining integrity reads. Prior data, metadata, namespace and both directions of the hardlink partition are checked. Native validation reads compressed logical content without trusting SEEK_DATA; valid compressed candidates are regenerated from RAM instead of cloning decmpfs state. Tiny-file cloning can cost more elapsed time than rewriting; reduced disk payload does not imply universal speedup.

Coordinator lock order is volume transaction, then short repository/configuration lock. Name/path resolution binds a UUID before waiting, refreshes that same Folder inside the lock, and passes it through continuations. Different volumes can save independently. A journal commit publishes only the captured generation. Journal/adoption failure does not advance caller authority. Quiesce stays frozen through successful unmount. Failure must durably invalidate the quiesced receipt before thaw; failure to durably invalidate leaves RAM frozen. New helper receipts also bind the helper incarnation and current live generation/frozen state read under one tree lock. Frozen reads do not update atime, so quiesce metadata stays immutable through unmount. Thaw/write/refreeze cannot make an older exported generation current again. Legacy helpers retain PID/session compatibility and do not supply a cryptographic incarnation identifier.

Restore verifies stage and data directory identities, the complete remaining content, already moved entries, and hardlink equivalence across their boundary before another move. Move-before-journal replay is supported. Per-entry no-replace rename, directory fsync and journal checkpoints are deliberately retained for crash safety. Cleanup's independent writer race was not redesigned as part of these optimizations; recovery/error gates and existing cleanup tests remain in place. Directory caches check cached ancestor identity; iteration and cleanup use bounded live descriptors. Directory handles pin immutable name snapshots with stable cookies and account for their final external reference.

Native Debug and optimized tests, isolated Swift regressions, protocol scenarios and measured performance evidence are recorded by original finding number in the remediation run's implementation-result.md and acceptance.json. Parent host Xcode/asset build, XCTest, mounts and independent acceptance remain separate gates.

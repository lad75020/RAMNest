Data Safety
This page answers the uncomfortable questions: what is guaranteed,
what isn’t, and what to do when something goes wrong. It assumes you
have read Synchronization, in
particular the three copies of your data (RAM, snapshot, folder).
What is guaranteed, and what
isn’t?
- Guaranteed: with Sync RAM folder
on, every cooperative unmount saves your work into the folder. That
covers ejecting from the app, Finder or the command line, quitting the
app, a normal shutdown or restart, and ejecting while the app is
closed.
- Not guaranteed: anything that cuts power to RAM
without warning. A power cut, a kernel panic or a forced restart runs no
save, and changes since the last save are gone.
- The safety net in between: Save RAM folder
periodically keeps the snapshot fresh while mounted, so a crash
costs at most the work since the last periodic save, provided
you rescue the snapshot before remounting.
My
Mac crashed or lost power while a RAM folder was mounted. What
survives?
A hard stop runs no save. Afterwards:
- Your folder holds what it held at the last
completed unmount, usually its contents from before the last mount.
- The snapshot holds the last periodic save, if
periodic saves were on. It can be much newer than the folder.
- What was in RAM since then is gone. Nothing can
bring it back.
If the snapshot may be newer than your folder, copy it somewhere
safe BEFORE mounting the RAM folder again.
Mounting refreshes the snapshot from the folder, because the
folder is the source of truth while unmounted. After a crash the folder
is stale, so the next mount overwrites the newer snapshot with older
data. The recovery window closes the moment you remount, and remember
that Mount at launch remounts as soon as RAM Folder
starts.
To rescue it, open ~/Library/Application Support/RAM
Folder/sync/<folder-name>-<id>.noindex/snapshot/ in
Finder (Go › Go to Folder…, or ⇧⌘G),
copy the whole snapshot folder elsewhere, then mount and
merge by hand.
If the snapshot is older than your folder (no periodic saves), there
is nothing to rescue: the folder already holds your last saved
state.
Only
RAM Folder crashed, not the Mac. Did I lose anything?
No. A mounted RAM folder belongs to macOS, not to the app, so it
stays mounted and fully usable after an app crash or a force quit.
Relaunch RAM Folder: it recognizes the volume as already mounted and
takes it back over. Eject it normally whenever you like, and your work
is saved.
What happens if a save fails?
A save has four steps: copy RAM into the snapshot, write a marker,
unmount, then copy the snapshot into your folder. The critical window is
after the unmount. RAM is already gone, the folder still shows old
contents, and your work exists in exactly one place: the snapshot.
The save sequence: copy RAM into the
snapshot, write the sync-pending marker, unmount, then copy the snapshot
into the folder. On success the marker is deleted. On failure it stays,
and the snapshot is trusted over the folder.
The eject-with-save sequence and its one risky window.
To make this window safe, RAM Folder writes a marker
(mirror-pending.json) next to the snapshot just before
unmounting, and deletes it only once your folder is up to date. If the
last copy fails (permissions, a full disk, locked files), or the Mac
crashes in the middle of it:
- the volume stays unmounted and RAM Folder reports the problem
(“Saved with issues” in the eject or quit window);
- the marker stays, so RAM Folder knows your folder is stale and
the snapshot is the authoritative copy.
While the marker is present, the next mount is deliberately
careful:
- the snapshot is not overwritten from the stale
folder. Files you added to the folder in the meantime are merged in, but
nothing in the snapshot is deleted or replaced;
- your RAM folder is restored from the snapshot, so your last session
is back.
One side effect: files you deleted during the failed session
can reappear, because they are still in the stale folder and the careful
merge doesn’t remove them. That is preferable to losing files you
added.
The marker clears itself the first time a save completes. Most
failures are temporary: fix the cause, then mount and eject once. RAM
Folder fixes one common cause itself: files carrying Finder’s
Locked flag. It clears the flag and retries once.
I
deleted a RAM folder with Keep folder and the save failed. Where are my
files?
Keep folder saves the RAM contents into the folder
before removing the RAM folder. If that final copy fails, RAM Folder
does not delete the snapshot. It moves it into a quarantine folder:
~/Library/Application Support/RAM Folder/recovered/<name>-<date>/
and shows a Disk Removed — Files Preserved alert
with a Show in Finder button. Your session’s files are
inside, under snapshot/. Copy them where they belong once
you have fixed what blocked the save.
The same quarantine applies whenever RAM Folder removes a RAM folder
whose last save never finished: the snapshot is kept, not deleted.
Does Delete folder keep
anything?
No. Delete folder unmounts the RAM folder without
saving, then deletes the folder from your disk. Both the RAM contents
and the folder’s files are gone. Use it only for data you really want
removed; otherwise choose Keep folder. See Creating
a RAM folder.
What
does RAM Folder do at quit if RAM folders are still mounted?
It saves them before quitting. A Saving RAM folders before
quitting window lists every mounted RAM folder that has
Sync RAM folder on:
- A RAM folder that no app is using starts saving right
away, in parallel with the others. If nothing is in use,
quitting needs no click at all: the window only shows progress, then the
app quits.
- A RAM folder that apps still use waits for you: quit those apps
(Quit per app, or Quit all), or
Ignore them. See Mounting
& ejecting.
- Cancel stops the saves still in progress, but
does not remount RAM folders that already finished.
Their data is safely in the folder, and you can mount them again from
the app.
- If a save fails, the window offers Quit Anyway or
Stay. Quit Anyway keeps the
failed-save protection described above: your data is in the snapshot,
and the next mount uses it.
Temporary RAM folders (Sync RAM folder off) are
unmounted without a question, since there is nothing to save.
Do RAM folders survive sleep?
Yes. Sleep keeps RAM powered, so mounted RAM folders and their
contents are intact on wake. The risky events are the ones that cut
power to RAM: power loss, a forced restart, or a battery that runs
completely flat. Treat those like a crash (see above).
What is the best
setup for data I care about?
- Keep Sync RAM folder on.
- Turn on Save RAM folder periodically, with an
interval matching how much work you can afford to lose.
- Keep the folder inside your backups. After each clean eject it holds
everything.
- After a crash, rescue the snapshot before
remounting, and consider turning off Mount at
launch for that RAM folder until you have.
- Don’t treat the snapshot as a backup: it has no history and is
overwritten at every mount.

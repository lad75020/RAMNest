Mounting and Ejecting
How do I mount or eject a
RAM folder?
- In the app: use the mount / eject button on the RAM
folder’s row in the sidebar.
- In the menu bar: open RAM Folder’s menu-bar panel
and use the Mount / Unmount button
next to the RAM folder.
- In Finder: eject it like any volume, when it is
visible in the sidebar (with Hide from Desktop and Finder
sidebar off).
- In the Terminal:
ram-folder mount <ref> and
ram-folder unmount <ref>; see Command line.
While a RAM folder is mounting, its row shows Loading from
disk…: its files are being copied into RAM. While it is
ejecting, it shows Saving to disk…: its files are being
saved into the folder. Both show progress.
What exactly
happens when I mount and eject?
At mount, the folder’s current files are copied into
a fresh RAM volume mounted on the same path. At eject,
with Sync RAM folder on, the RAM contents are saved
back into the folder, and the RAM volume is removed. The whole mechanism
is explained in Synchronization.
Why does ejecting show a
list of apps?
A volume can’t be unmounted while a program uses it, and saving files
that are still being written risks saving them half-finished. So before
ejecting (or quitting), RAM Folder lists the processes using the RAM
folder. Each is shown as either:
- Opened files: the app has files open on the RAM
folder. Hover over the indicator to see which ones. An app running
from the RAM folder counts too.
- Working in directory: the process only has its
current directory there. The classic case is a Terminal window whose
shell sits in the folder: it holds no files, but still blocks the eject.
Run cd ~ in that shell and it disappears from the
list.
For each process, you can:
- Quit: asks the app to quit, as if you chose Quit in
it. If it doesn’t quit (for example because it is showing an
unsaved-changes dialog), Force Quit appears after a
moment. Force-quitting discards that app’s unsaved work.
- Ignore: leaves the app running and proceeds anyway.
The first time, RAM Folder warns that “Saving while apps have files
open can capture a partial write. The saved copy may be inconsistent,
and the volume may not unmount cleanly.”
Quit all and Ignore at the bottom
apply to every process at once; Cancel keeps the RAM
folder mounted. The list updates live: as soon as no process is left,
the save starts.
A process is listed if it uses any file anywhere in the RAM folder,
not only in the subfolder you are looking at.
I
ejected from Finder and got “eject failed”, but the RAM folder ejected
anyway. Why?
That is expected. For a RAM folder with Sync RAM
folder on, the save must run before the unmount. When
the eject comes from outside RAM Folder (Finder,
diskutil unmount, umount), RAM Folder holds
that request back, which Finder reports as a failure, runs the save, and
then completes the eject itself a moment later. The end result is what
you asked for: data saved, RAM folder ejected.
This works whether or not the app is running: when it is closed, the
background helper does the same. It does not apply to a Force
Eject, which skips the save.
What
happens if a RAM folder is unmounted without a save?
After a forced eject, or anything else RAM Folder couldn’t hold back,
the app notices within a few seconds and shows the RAM folder as
unmounted. No save ran: the folder holds its last saved state, and the
snapshot holds the last periodic save, if any. If the newest data was in
RAM, treat it like a crash: rescue
the snapshot before mounting again.
What
happens when I quit RAM Folder with RAM folders mounted?
RAM Folder saves and ejects every mounted RAM folder that has
Sync RAM folder on, in the Saving RAM folders
before quitting window. Those not used by any app start saving
right away, in parallel. Those still in use wait for you to quit or
ignore the apps using them, as described above. Temporary RAM
folders are simply unmounted. Details, including
Cancel, Quit Anyway and
Stay, are in Data
safety.
A normal macOS shutdown, restart or logout quits RAM Folder the same
way, so your RAM folders are saved before the Mac goes down.
Does
“Mount at launch” mount my RAM folders at startup?
At app launch. Turn on Open at login in the
settings popover so the app itself starts when you log in: together they
give you RAM folders that are ready at every login. If a RAM folder
can’t be mounted at launch, RAM Folder shows a notification.
At each launch, RAM Folder also checks what is actually mounted. A
RAM folder that is still mounted (after an app crash, for example) is
taken back over as-is, not mounted twice.
The
app quit or crashed while a RAM folder was mounted. Is it gone?
No. A mounted RAM folder belongs to macOS, not to the app: it stays
mounted and usable. When RAM Folder starts again, it recognizes it and
takes it back over. Ejects are saved even while the app is closed.
Can two RAM
folders share a folder, or be nested?
No. Each RAM folder owns exactly one folder. RAM Folder refuses a
folder that already belongs to another RAM folder, a folder inside a
mounted RAM folder, and a folder that contains a mounted volume.
Can
the app and the command line work on the same RAM folder at once?
They share the same RAM folders, and changes made with
ram-folder appear in the app within moments. While one of
them is mounting, ejecting or deleting a RAM folder, the other leaves
that RAM folder alone until it is done, so two saves never run on the
same RAM folder at the same time.

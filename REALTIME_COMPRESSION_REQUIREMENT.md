# User clarification — transparent real-time compression

Latest direct instruction: **“add a compression functionality : the Ramdrive filesystem must compress its content in real-time.”**

Implement actual app-level transparent per-block compression in MemoryFS, not merely relying on macOS swap/compression. Use Apple's system Compression.framework (e.g. COMPRESSION_LZ4 for fast write-time compression, no new downloads). On every write/partial write: decode old block to bounded scratch, modify, encode, atomically replace backing only after success. On reads decode just requested blocks; sparse holes stay implicit zeros. Store incompressible data raw when encoding does not save actual backing pages. Use mmap/munmap backing so truncation/unlink return physical memory as already required. Capacity must remain a safe uncompressed content ceiling to prevent compression bombs; separately expose uncompressed content bytes, compressed payload bytes, mapped backing allocation and savings/ratio (metadata/cache overhead disclosed). Do not advertise compressed payload length as measured whole-process RSS.

IMPORTANT on this arm64 host VM pages are16384 bytes. Compressing each16KiB block into its own mmap still commits16KiB for tiny compressed output and saves NO physical backing. Choose a larger logical compression block (e.g.64KiB or256KiB) with exact mapped-length page rounding, or a reclaimable packed/slab design. Verify actual resident memory reduction for highly compressible data vs same-size incompressible data; verify real munmap reclamation. Keep maximum block/workspace/decode sizes bounded; corrupt/compression-error paths return EIO and never erase last valid data. Handle partial overwrites, truncate within a block and growth zeros, sparse offsets, hardlinks/open handles, concurrency and snapshot export/import correctly. Reconcile manifest capacity preflight with logical block accounting so lots of small files cannot undercount.

Expose a clearly labelled real-time compression option/default (on is sensible) in creation/detail UI and CLI, persist it, and accurately describe it. Existing raw storage can be retained for compression disabled; setting can be next-mount-only with explicit UI if live recompress unsafe. Include native round-trip/random/partial-write/corrupt-block/failure/concurrent and physical-footprint tests plus actual mount save/eject/remount checks with compression. No S3: LOCAL_ONLY_SCOPE.md remains in effect. All other app functionality remains required. Add compression behavior to feature/FUSE matrices and README, avoiding unsupported speed guarantees.

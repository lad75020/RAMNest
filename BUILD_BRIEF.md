# RAMNest implementation contract

**Scope override from the user: local storage only. Do not implement S3 or other remote storage. LOCAL_ONLY_SCOPE.md supersedes all historical remote-storage requirements below. CONTENT_PROPORTIONAL_MEMORY.md and FUSE_COVERAGE_REQUIREMENT.md contain additional mandatory user clarifications.**

Create an independent native macOS SwiftUI app in this directory. Do not modify sibling RAMDrive or the Code container. No commits, pushes, root installs, TCC/security changes, or real user-data mutations. All smoke tests use disposable directories under $TMPDIR or this project's artifacts. Never read secrets/credential files. macOS 27.2 host; Swift 6.4/Xcode 27, CMake and XcodeGen available. Prefer SwiftPM app/core/CLI/test targets plus build/package scripts and an Xcode project if practical. This is implementation, not planning-only.

## User requirements
Match operational functionality documented at https://less-software.sh/ram-folder/help-center (read all linked functional help pages if needed), but replace its tmpfs backend with FUSE-T (https://github.com/macos-fuse-t/fuse-t/wiki). Distinct branding RAMNest; do not reproduce vendor license/trial restrictions, private analytics or update server. Explicitly record those distribution differences. User chooses an existing folder; preserve its data in verified private on-disk storage, empty the selected mountpoint safely, mount memory filesystem AT THAT SAME PATH, then copy selected-folder data into the mounted RAM volume. Do not silently use hdiutil, native RAM devices, tmpfs or a disk-backed mirror. Size is a ceiling, not an eager reservation, deletion must release backing allocation. FUSE-T installed at /Library/Application Support/fuse-t with lib/libfuse-t-1.2.9.dylib and include/fuse (FUSE2), also include/fuse3 and lib/libfuse3.4.dylib. Use private explicit include/lib/rpath, never global macFUSE headers. No root should be necessary. Real host mount tests may fail in Codex sandbox; hand exact commands back to parent, do NOT bypass sandbox.

## Reference feature checklist
- Multiple named RAM folders, unique case-insensitive names, path/name/ram://percent-encoded-name references, persist configurations and shared app/CLI state safely. Drag/drop and folder chooser; new creation sheet with size MB/GB and optional name; reject root/home/system folders, Containers/Group Containers, symlink traversal, existing foreign mounts, nested/duplicate/overlapping RAM folders, app support nesting; reject source too large before moving files. Track renamed/moved folders via bookmarks/file identity where possible, fail safely if uncertain.
- Sidebar status, detail capacity used/total + name edit and resize, reveal/open in Finder, mount/eject/save/delete/recover controls, state/progress/error display. Native responsive UI, menu-bar and Dock mode, startup mount, SMAppService login setting; system memory bar. Normal/Advanced settings with Apply/Discard and unsaved-change safeguards.
- Defaults: mount at launch true, nobrowse true, sync true, periodic save off, interval 15 min; 5/15/30/60/360/720/1440 min choices; FSEvents suppression optional, size+mtime vs checksum comparisons. Do not advertise unsupported FUSE options: explain FSEvents support limitation if backend cannot honor it.
- True in-process RAM content storage in detached per-volume helper/daemon (C/C++ recommended for FUSE), normal files/directories, sparse writes/truncation, capacity ENOSPC, rename, symlink, hardlink/open-handle unlink semantics, read/write offsets, reasonable statfs/mode/timestamps and xattrs where feasible. Thread safety. Allocation bound checked for offsets/overflow; no disk writes of payload outside explicit save operations. Helper survives GUI crash, discovers/reconnects on restart. Ensure file descriptors are closed on spawn (especially inherited stdout pipes) so CLI exits after daemon launch. Parent can run real host mount tests.
- Durable local transaction journal, private 0700 snapshot dirs, verified snapshot BEFORE source removal/moving, rollback on every failure, only delete/move exact selected managed entries not guessed paths, safe symlink handling, source write race checks and mounted identity checks. Retain original copy until RAM population verified. Eject/save must use a coherent frozen view or quiesced writes; do not lose writes between snapshot and unmount. Snapshot is last-known committed data, pending-restore marker trusted after crashes; never overwrite newer snapshot with stale/empty mountpoint. Startup recovery gate before auto-mount if unclean. Never delete only recoverable copy. Atomic snapshot promotion with prior-good fallback. Save failure leaves recoverable files and explicit state; synchronization off restores original folder unchanged. Prefer safer blocking recovery to opaque merge.
- Clean GUI quit saves/ejects all volumes, can cancel/stay on failure; no actual host shutdown test. External Finder/diskutil/umount eject while GUI absent must save from helper-held memory and restore original path if possible. Since FUSE destroy can occur after mount disappears, helper can retain live RAM tree through callback; document exact guarantee and test. Busy process detection, cancel/ignore and safe termination only on explicit request; do NOT kill apps during tests. Forced eject/power cut limits explicit. On helper crash, preserve latest durable snapshot and recover at next launch. Temporary mode preserves initial folder.
- Periodic save updates snapshot, final eject restores selected folder. Resize mounted volume losslessly (including temporary mode), reject shrink below usage, safe resume on errors. Capacity reported on filesystem; memory backing lazily allocated and reclaimed.
- S3-compatible remote snapshots with AWS SigV4 or dependable adapter; provider presets/custom HTTPS endpoint + bucket/prefix/region, validate before apply, credentials in Keychain (NOT config/logs/argv). Remote save failure local fallback, later retry with exact revision semantics, no silent stale remote overwrite or losing fallback. Never contact real bucket without user config. Include local fake/mock signed-request tests and mark actual cloud roundtrip UNVERIFIED unless tested. Can use archive snapshot object with clear semantics/metadata caveats instead of file-level sync; document deviation.
- CLI bundled in app and usable headlessly: --help/--version/list or ls (--all/--json), info, create path --size and options, mount/unmount/save/resize/delete (--keep default safer; destructive delete explicit confirmation), recover/export snapshot, remote list/setup/info/unset/retry. Cross-process locking for app/CLI/daemon. No hidden mandatory sudo. CLI installation explicit user action into user-selected directory or ~/.local/bin, no automatic system installation. JSON output and nonzero actionable exit statuses.
